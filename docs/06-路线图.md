# 06 · 路线图

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| **M1** | `ingest` + `core` + 8 个纯本地检查 + 终端报告 | 同一 commit 重复运行分数完全一致；在 10 个真实仓库上人工复核分数合理 |
| **M2** | 补齐全部检查项 + `--remote` + JSON schema 冻结 + `--min-score` | 能作为 CI 门禁使用；JSON 输出结构定稿 |
| **M3** | `badge` + `report` + `init` + composite action + cargo-dist 首个 release | **GitHub 代码搜索能搜到外部仓库挂了 badge** |
| **M4** | `repolish-md` 增量改写 + `polish --apply` | 30 个 fixture README 的往返测试全绿；改写不破坏原文 |
| **M5** | `repolish-llm` + LLM 增强建议 | — |

## 关键判断

**M3 是生死线。** 在此之前不要碰 LLM——分数本身立不住的话，AI 生成的内容也没人信。

M1 的 8 个检查项全部选择**无需网络**的（见 [05-评分维度.md](05-评分维度.md)），确保默认路径零配置可跑。

M4 之前先建 `fixtures/`：收集 30 个真实 README（覆盖不同语言、长度、风格），作为增量改写的回归基线。

## 明确的非目标

- 托管服务、排行榜、Web 站点
- 代码质量 / 安全扫描（scorecard 已做好，必要时在报告里链接过去而非重复实现）
- 从零生成 README（readme-ai 的领域）

## M1 完成情况（2026-08-19）

已交付：workspace 六个 crate、`Check` / `Outcome` 四态模型、风险加权聚合与分母保护、
Profile 探测、8 个本地检查项、终端与 JSON 输出、5 个退出码。
`cargo test` 19/19 通过；同一 commit 重复运行输出逐字节一致。

### 与设计文档的偏差（有意为之，非遗漏）

| 项 | 实际做法 | 原因 |
|---|---|---|
| 语言统计未用 `tokei` | 按扩展名自行计数 | M1 只需粗粒度信号；`tokei` 编译成本高，M2 接入时一并做语言分布 |
| `gix` 只取 HEAD 提交时间 | 未做贡献者 / release 节奏 | `activity` 检查项够用；M2 补 |
| 分母保护的分母 | 本次运行**注册**的检查项，而非 v1 全部 22 项 | 否则 M1 只注册 8 项（占 v1 总权重 49%）会永远触发保护、永不出分 |
| 内容统计排除点目录 | `.trae/`、`.vscode/` 等不计入语言统计 | 实测中 `.trae/skills/` 里的 6 个 md 把一个空仓库误判成文档站 |

### 验收：12 个真实开源仓库

复现方式：`./scripts/fetch-fixtures.sh`（仓库不入库）。选型覆盖 Rust / Python /
JS / Go / Java，以及库、CLI、文档站、资源集合四种形态。

初次运行 12 个仓库暴露 **9 个真实缺陷**，全部已修并加了回归测试：

| # | 症状 | 根因 |
|---|---|---|
| 1 | ripgrep 判「无标题」 | 只认 ATX 标题，不认 setext（下划线式，级别是 h2） |
| 2 | axios / chalk / fzf 判「无标题」 | HTML 标题（`<h1 align="center">`）被 comrak 归为 HtmlBlock，不走 Heading 节点 |
| 3 | ruff / axios / fzf / koa 判「区块无命令」 | 区块边界按「下一个任意级标题」切，子标题会截断父区块 |
| 4 | koa 判「区块无命令」 | 只取首个候选区块，命中空的 `Getting started`，跳过了有命令的 `Installation` |
| 5 | advanced-java 全部链接判失效 | 链接是 `/docs/x.md` 这种根绝对路径，`Path::join` 遇绝对路径会丢弃基路径 |
| 6 | serde 判「无 LICENSE」 | 不认 `LICENSE-MIT` / `LICENSE-APACHE`，而 Rust 生态双协议是惯例 |
| 7 | ripgrep 判「许可证认不出」 | 按字母序只看第一个候选，撞上仅作指路用的 `COPYING` 就不再看别的 |
| 8 | requests / ripgrep 判「CI 没跑测试」 | 匹配 `cargo test` 这类固定串；实际写法是 `${{ env.CARGO }} test`，或步骤名与命令分行 |
| 9 | serde / tokio 判成 CLI | 命中 `test_suite/no_std/src/main.rs`、`tests-integration/src/bin/` 等测试夹具 |

修复过程中又引出三个次级问题，同样已修：

- 放宽到「首个任意标题」后，axios 把第 453 行的 `## Table of contents` 当成了项目名
  → 标题必须在文档开头附近，且级别不低于 h2
- 「整块含 sponsor 字样就跳过」误伤 fzf / awesome：它们开头块里有个 `alt="Sponsors"`
  徽章，真 logo 被一起丢掉 → 改为按候选位置取最靠前的，并加一条「真标题不会是超链接」
- serde 标题混入徽章 alt 文本、chalk / ruff 的说明取到徽章行与导航行
  → 提取标题与说明时跳过图片子树，并识别「只有链接与分隔符」的导航行

### 已知限制（未修，记录在案）

- **axios 的标题取到赞助商图片 `Thanks.dev`**。该 logo 没有包在 `<a>` 里，
  现有规则挡不住。分数（5 分「标题是图片」）与结论方向正确，只是引述的名字不对。
- **M1 的 8 个检查项区分度不足**：12 个成熟仓库中 4 个落在 92–100。
  真正拉开差距的 `repo-description`、`repo-topics`、`claim-consistency`、
  `release-hygiene` 都在 M2，分数分布要等 M2 之后再评估。
- **`docs` 与 `collection` 的边界模糊**：advanced-java 的外链少、内链多，
  被判为 `docs` 而非 `collection`，于是仍要求它有「快速开始」。

### 新增的工程约束

- `tests-present` 必须识别内联测试（Rust `#[cfg(test)]`、Go `func Test`），
  且标记须在行首——否则会命中源码里的字符串字面量
  （本检查项一度扫中了自己的 `INLINE_MARKERS` 定义）
- Windows 上路径统一走 `dunce::canonicalize`，避免 `\?\` 前缀泄漏到用户可见输出
- 解析测试里的引用式链接必须给出定义，否则 comrak 当作纯文本，测不到真实行为

## M2 完成情况（2026-08-19）

已交付：v1 的 **22 个检查项全部实现**、`--remote`（GitHub API）、**JSON schema 冻结于
`schemaVersion: 1`**、`--min-score` 门禁与退出码 4。`cargo test` 55/55 通过；
同一 commit 重复运行输出逐字节一致。

### 与设计文档的偏差

| 项 | 实际做法 | 原因 |
|---|---|---|
| GitHub API 客户端 | `ureq` 而非 `octocrab` | 远程需求只有一个 `GET /repos/{owner}/{repo}`。octocrab 带进 tokio + hyper，会把全同步的 CLI 拖成异步，也拖慢 M3 的静态二进制。已同步改 [03-技术架构.md](03-技术架构.md) |
| `readme-length` 增加不适用规则 | `collection` 下 `NotApplicable` | 资源集合的 README 就是内容本体，长是形态不是缺陷。已补进 [05-评分维度.md](05-评分维度.md) |
| `readme-toc` 短 README 判满分 | 不用 `NotApplicable` | 「达标」与「不适用」不同：后者会把该项剔出分母，抬高其余项占比 |
| 语言统计仍未用 `tokei` | 继续按扩展名计数 | `repo-topics` 的交叉验证只需要「主语言是什么」，粒度够用 |
| `.repolish.toml` 未实现 | `--only` / `--skip` 已够做 CI 门禁 | 配置文件顺延到 M3 与 `init` 一起做 |

### 验收：同一批 12 个真实仓库

暴露 **6 个真实缺陷**，全部已修并加了回归测试：

| # | 症状 | 根因 |
|---|---|---|
| 1 | ruff / fzf 的 `claim-consistency` 判 0 分 | 把用法示例里的路径当成了「仓库的承诺」：`curl https://…/install.sh` 是远端脚本，`path/to/code/to/file.py` 是占位符，`fzf-preview.sh` 是裸文件名 |
| 2 | ruff 的失效声明里出现 `.py` | 行尾注释没剥掉，注释里的 `` `.py` `` 被当成文件路径 |
| 3 | axios / flask / fzf 判「首屏没有徽章」 | 徽章写在 HTML `<img>` 里，comrak 归为 HtmlBlock，不是 Image 节点——整个首屏对解析器不可见 |
| 4 | axios 的 opencollective 赞助 logo 被当成徽章 | 赞助商图片与 shields 徽章同域，域名不足以区分 |
| 5 | ripgrep 判「不用语义化版本」 | 浅克隆只带下恰好指向 HEAD 的那一个 tag（`ignore-0.4.33`，子 crate 的），据此推断发布节奏必然错 |
| 6 | ripgrep 的文档站被认成 `docs.rs/regex` | 那是它**依赖**的文档。`docs.rs` / `pkg.go.dev` 这类站点按包分页，只看域名会把别人家的文档算到自己头上 |

另有两处漏判，一并修了：serde / tokio 的 workspace 根清单没有 `[package]`，
取不到包名导致 `readme-install-consistency` 无从比对（改为回落到与仓库同名的成员
crate）；fzf / awesome 的文档在根目录（`ADVANCED.md`、`create-list.md`）与 `man/`、
`doc/` 下，只数 `docs/*.md` 会判成「没有文档」。

分数分布从 M1 的 73–100 拉开到 **62–97**（requests 97 / ruff 96 / tokio 93 …
awesome 80 / advanced-java 62），M1 记录的「区分度不足」已解决。

### 已知限制（未修，记录在案）

- **`claim-consistency` 在这 12 个仓库上全部 `Inconclusive`。** 不是失效——用
  合成仓库验证过判定正确（5 条可校验、准确抓出 2 条失效、不误伤 `npm run build`
  与 `./scripts/setup.sh`，见 `crates/repolish-checks/tests/claims.rs`）。原因是
  成熟库的 README 只写安装与用法，很少出现 `npm run` / `make` / `./scripts/` 这类
  仓库内部命令。这是**为精确率主动付出的召回率代价**：宁可不判，不可错判。
  应用型仓库与 monorepo 才是这一项的目标人群，验收样本里恰好一个都没有。
- **`release-hygiene` 在浅克隆下一律 `Inconclusive`**，因此 12 个 fixture 全部命中。
  这是有意为之：`actions/checkout` 默认 `fetch-depth: 1`，而那正是我们希望用户
  长期挂着的环境，一条系统性误判足以让人卸载工具。M3 的 workflow 模板要默认带
  `fetch-depth: 0`。
- **`readme-i18n` 12 个仓库全判 5 分**（无译本的起评分）。判定本身是对的，
  但一项对绝大多数项目给同一个分的检查，区分度接近零。权重已是最低的 Low，
  影响约 0.9 分，暂不处理。
- **`docs-presence` 认不出不含项目名的自建文档站**（fzf 的 `junegunn.github.io/fzf/`
  靠根目录的 `ADVANCED.md` 才拿到分）。要修得靠链接文本（「Documentation」「文档」），
  而 `LinkRef` 目前不存文本。

### 新增的工程约束

- `toml` 0.9 的 `Value: FromStr` 解析的是**值表达式**而不是文档，`"[package]"` 会被
  当成数组。解析清单必须走 `toml::from_str::<toml::Table>`
- 命令行提取必须剥掉行尾注释，且只认 `./` 锚定或首段确为仓库目录的相对路径——
  README 的用法示例里到处是使用者自己的文件
- 徽章 / logo 判定不能只看域名：赞助商图片与 shields 徽章同域
- HTML `<img src>` / `<a href>` 已在 `repolish-md` 统一提取，行号按标签在块内的
  相对位置换算（HTML 块常跨十几行，全记成块首行会让证据指错地方）
