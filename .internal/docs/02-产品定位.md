# 02 · 产品定位

## 一句话定位

把**可发现性**（description / topics / SEO）、**可理解性**（README 首屏 / 快速开始 / 示例）、**可信度**（License / CI / 测试 / 活跃度）打成一个可复现的分数，配上徽章与可落地的改进建议。

服务对象：**已经存在的开源项目**——不是帮你从零写 README，而是告诉你现在这份差在哪、并把它补好。

## 目标用户

- 有代码但文档薄弱的个人开源作者（主力）
- 需要统一多仓库文档质量的小团队 / 组织
- 准备把内部项目开源的工程师（对应 repo-audit 的场景）

## 核心指标

| 阶段 | 指标 |
|---|---|
| 早期 | 通过 GitHub 代码搜索能找到多少仓库挂了我们的 badge |
| 中期 | Action 装机量（workflow 文件数） |
| 长期 | `polish --apply` 后的改动被 commit 的比例 |

---

## 形态决策：仅 CLI

**已确定不做托管服务。** 不承担域名、数据库、GitHub API 配额、SVG 流量的长期运维。

代价是回链的载体必须重新设计——下面这套方案在零运维前提下仍能拿到完整的徽章 + 回链闭环。

---

## CLI-only 的传播闭环

核心思路：**把「服务端」换成用户自己的 CI + shields.io**。

### 1. 徽章走 shields.io 的 endpoint 协议

CLI 生成 `.repolish/badge.json`：

```json
{
  "schemaVersion": 1,
  "label": "repolish",
  "message": "88/100",
  "color": "brightgreen",
  "repolishVersion": "0.3.1"
}
```

README 中的代码：

```markdown
[![Repolish](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/OWNER/REPO/main/.repolish/badge.json)](https://github.com/OWNER_OF_REPOLISH/repolish)
```

图片由 shields.io 免费渲染，数据从**用户自己仓库**的 raw 读取，**链接指向我们的仓库**。零基础设施，完整的 badge + 回链。

> `repolishVersion` 必须带上：评分口径变更后，各仓库的 badge 会长期处于不同版本，需要能识别。

### 2. 自动更新靠用户的 GitHub Action

Action 中执行 `repolish check . --badge`，分数变化则 commit 回仓库。**「实时更新」由用户的 CI 完成**——这是 CLI-only 拿到「活徽章」的唯一路径，必须做。

顺带把分数写入 `$GITHUB_STEP_SUMMARY`，每次 Actions 运行页顶部即有一张健康度卡片，是免费曝光位。

### 3. 报告页 = 仓库内的 `REPOLISH.md`

`repolish report .` 生成带证据与改进清单的 Markdown，落在用户仓库里，页脚固定一行 `Generated by [repolish](...)`。该文件本身是 SEO 资产——GitHub 上每多一个仓库有它，就多一条索引。

### 4. 建议以可合并的变更落地

`polish --apply` 直接改文件，用户自己 commit。在 Action 中则配合 `peter-evans/create-pull-request` 自动开 PR——把这段写进我们提供的 workflow 模板即可，等价于 Gitee 的 PR 交付体验。

## 明确放弃的东西

| 失去 | 影响 | 缓解 |
|---|---|---|
| 中心化排行榜 / 发现页 | 少一个强传播点 | 无。接受 |
| 使用量统计 | 无法直接观测采用率 | 在生成的 snippet 中埋唯一字符串（`.repolish/badge.json` 路径），用 GitHub 代码搜索计数 |
| 我们可控的报告详情页 | 回链落点是仓库首页而非报告页 | 用 `REPOLISH.md` 承接；徽章链接指向项目仓库 |
| 秒级刷新的徽章 | raw.githubusercontent CDN 缓存 ~5 分钟，shields.io 另有缓存 | **文档中不承诺「实时」**，只说「每次 CI 后更新」 |

## 留存逻辑

CLI-only 产品的留存靠**「进了 CI 就不会被删」**。因此两件事优先级高于任何功能：

1. `--min-score` 让它能当 CI 门禁用
2. `repolish init` 一条命令装好 workflow

## 暂不考虑

- WASM Web 入口（将来可用 GitHub Pages 零成本托管静态页，M5 之后再议）
- 托管 API / 排行榜
- 自建 SVG 渲染服务
